# 17 — Feature: Violations Register

## Goal

Every representative has a file. When he returns a machine with the wrong battery or no charger, the
hand-off is accepted and the incident is recorded against him. Supervisors and the Director can open
that file at any time.

## Screens

| Page | Route | Permission |
|---|---|---|
| `ViolationsListPage` | `/violations` | `violations.read` |
| `ViolationDetailPage` | `/violations/:id` | `violations.read` |
| `ViolationFormPage` | `/violations/form` | `violations.create` |
| `UserViolationsPage` | `/users/:id/violations` | `violations.read` |
| `MyViolationsPage` | `/violations/mine` | any authenticated |

`AutoGeneratedBadge` matters: a violation the system detected carries different weight from one a

## ViolationDetailPage

1. `ViolationHeaderSection` — type, severity, status, date
2. person held responsible, with a link to their file
3. `ViolationContextCard` — the machine and the transfer that produced it, tappable through to both
4. `ViolationEvidenceSection` — the photos captured during that hand-off. This is why photos are
   taken at all; make them prominent.
5. description
6. `ViolationActionsBar`, permission-filtered

### Actions

| Action | Permission | Effect |
|---|---|---|
| إقرار بالاستلام | the responsible user only | OPEN → ACKNOWLEDGED |
| تحصيل مبلغ | `violations.resolve` | `ChargeViolationSheet` → creates income server-side |
| إعفاء | `violations.waive` | `WaiveViolationDialog`, reason required |

`ChargeViolationSheet`: amount, date, payment method, notes, and a preview line —
"هيتسجل إيراد ٣٥٠ ج.م تحت قسم مخالفات". Same principle as maintenance: never move money silently.

## MyViolationsPage

Every representative can see their own file, always, regardless of `violations.read.all`. Shown from
the home dashboard and their profile.

Tone matters here. This screen is read by the person being penalised, so:
- lead with facts, not judgement
- always show the evidence photos so they can dispute a wrong entry
- provide a clear path to raise a disagreement ("كلّم مشرف الفرع" with a call button)

## Rules

1. Violations are **never deleted** from the app. Waiving is the only way to close one without
   charging, and it requires a reason.
2. Auto-generated violations are read-only: no edit button at all, not a disabled one.
3. Charging is blocked if already charged — the button disappears and the amount shows instead.
4. Read-only offline from cache. Charging and waiving are online-only.
5. Never use punitive language in the UI. "مخالفة مسجّلة" not "مخالفة ارتكبها".
